## Downloads

| Platform | File |
|---|---|
| Linux x86_64 (glibc 2.35+: Ubuntu 22.04, Debian 12, Fedora 36 or newer) | `cadrs-v0.2.1-x86_64-linux.tar.gz` |
| Windows x86_64 (Windows 10 or 11) | `cadrs-v0.2.1-x86_64-windows.zip` |
| macOS 11 or newer, Apple silicon and Intel | `cadrs-v0.2.1-universal-macos.dmg` |
| A browser with WebGPU, such as Chrome or Edge | <https://cadrs.net/app/>, or `cadrs-v0.2.1-web.tar.gz` to serve yourself |

The Linux and Windows archives hold the executable, its `libraries/` folder (the built-in symbols, footprints and 3D models), the README and the licenses. Nothing needs installing: unpack it and run `cadrs` (Linux) or `cadrs.exe` (Windows), keeping `libraries/` beside it. `SHA256SUMS.txt` has the files' checksums.

On macOS, open the `.dmg` and drag cadrs to Applications. The app isn't signed with an Apple Developer ID yet, so the first time macOS won't open it: right-click cadrs in Applications and choose **Open**, then **Open** again (on macOS 15 and later, open it once, then choose **Open Anyway** in System Settings › Privacy & Security). Updates on macOS are downloaded from the release page and dragged over the old app.

On Linux, the app needs a Vulkan-capable GPU driver, and ALSA and udev (present on desktop distributions). The Windows build isn't code-signed, so SmartScreen may warn the first time: choose **More info › Run anyway**.

Documents are saved in `~/.local/share/cadrs/` on Linux, `%APPDATA%\cadrs\` on Windows and `~/Library/Application Support/cadrs/` on macOS.

## What's new since v0.2.0

- **cadrs in the browser.** Try it at <https://cadrs.net/app/>, with nothing to install. It is the same app as WebAssembly, drawn with WebGPU. Your documents stay in the browser's own storage. Exports download, and imports come from the browser's file chooser. The browser version has no sharing or working together yet, and no MCP server, updates or JLCPCB part search.
- **The network is off until you connect** (#148). cadrs no longer reaches out to the network when it starts:
  - A network button in the top bar shows whether you're online and when data comes and goes. Its menu has **Connect** and **Disconnect**.
  - **Share** and **Join** offer to connect first.
  - To go online every time, turn on **Preferences › Collaboration › Connect when cadrs starts**.
- **See where everyone is working.** In a shared document you see the others' mouse pointers live, each in that person's colour and with their name:
  - In a Part Studio or Assembly, a dot where their pointer touches a part (or the grid), and their camera, so you can see where they're looking from.
  - In a schematic, a board layout or a drawing, an arrow at the same point.
  - Each person has one colour everywhere, yours included.
  - "Alex joined" and "Alex left" notices.
  - The network menu lists who's here and in which tab. Click a name to follow them.
- **Working together, fixed:**
  - When the owner went offline and came back, edits stopped syncing. They now carry on.
  - An edit that can't reach the owner gives up after 15 s, rather than holding up every edit after it.
- **The system's own file dialogs** for Import, Browse… and every other file prompt (#136).
- **Tall dialogs scroll**, with their header and buttons kept in view, so a large UI scale can always be put back (#142).
- **Onshape import:** custom planes, and the sketches and features on them (#144).
- **The Material dialog** shows its whole list again, which scrolls past Brass to every material (thanks to Zach Strout). The library dropdown now opens in front of it.
- **Modelling:**
  - A chamfer wider than its wall runs on through it, as in Onshape, rather than failing.
  - An Add with a merge scope joins only the parts the new body touches.
- **A document saved by a newer cadrs** now shows a warning to update cadrs, where opening it used to do nothing.

cadrs is an independent project.
